# Original Mii Maker data to DS implementation

This project has the original **compiled** 3DS executable, not Nintendo's source code. ARM11/3DS OS calls and PICA rendering do not run directly on DS ARM9/ARM7 hardware. This map ties extracted original data and observed behavior to independently written DS code. It does not claim an original engine port or recovered function symbols.

`SOURCE_MAP.json`, generated by `tools/source_map.py`, inventories each original layout, every stored editor field and every embedded runtime asset with hashes. Binary string offsets provide provenance, not proof that an original function has been translated.

## melonDS startup correction

The custom `MDSD` game code makes melonDS use its retail-style cartridge reader, which also permits EEPROM saves. A DSi-enhanced image must give that reader a nonzero 512 KiB-aligned DSi-region boundary. The SDK's original packing left that field zero, causing all DS-mode asset reads to be redirected away from NitroFS. A blank reserved secure-area prefix was also classified as encrypted by the current core.

`tools/fix_nds_regions.py` runs automatically after SDK packing. It aligns and relocates the DSi payloads, sets the NTR/TWL boundary and lengths, adds the standard decrypted marker in the reserved prefix, and recalculates CRCs. ARM instruction streams and NitroFS files are preserved. The header remains DSi-enhanced; DS mode is the verified emulator configuration.

## Save behavior

melonDS defaults an unknown cartridge to an 8 KiB EEPROM. New saves use an 8 KiB bit-packed, checksummed snapshot containing all 62 fields and 100 slots. Unlike the old 64 KiB format, this compact layout has no second full bank: interruption while writing can invalidate a snapshot. Existing valid 64 KiB legacy saves continue using their two-bank recovery scheme on a correctly sized device. Unknown nonblank data is refused, and failure retains the in-memory draft. Physical hardware and flashcart mappings remain untested.


The current model/pose conversion and original transform-control wiring are detailed in `BODY_RENDERING.md` and `body-models.json`. The selected gallery Mii now uses a full-body view, while face previews use the source body/head attachment.

## Profile, dialogs and extracted font

`Editor/Profile`, original gender/birthday/color/sharing/copy dialogs and confirmation widgets map through `tools/profile_assets.py` and `profile-layouts.json` to `source/profile.c`, `source/main.c` and `source/ui.c`. Negative pane scales now also mirror their origin anchors in `tools/layouts.py`; this fixes overlapping half-buttons. `tools/number_font.py` maps the supplied Nintendo numeric BCFNT into native glyphs; `tools/banner_icon.py` maps the original SMDH icon to the DS banner. The ASCII touch keyboard is a DS adaptation and does not reproduce the original system keyboard.

`ANIMATION_RENDERING.md` maps 24 original Wait00 poses per body and records timing/renderer limits. Original geometry remains unchanged; the UI now composes complete top frames, prioritizes captured input and supports continuous body-slider dragging. Gallery SELECT exports a private BMP image to SD when sharing is permitted; encoder and absent-card paths are tested, physical writes remain unverified.
